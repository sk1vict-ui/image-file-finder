너는 숙련된 Python/Streamlit 개발자야.

Replit에서 바로 실행 가능한 “캡쳐 이미지 기반 원본 문서 찾기” 웹앱을 완성해줘.
설명용 목업이 아니라, 실제로 파일을 업로드하고 검색이 작동하는 완성형 앱이어야 한다.

앱 이름:
캡쳐 이미지 원본 파일 찾기

핵심 목표:
사용자가 캡쳐 이미지 1장을 업로드하고, 원본 후보 파일 여러 개를 업로드하면,
캡쳐 이미지가 어느 원본 파일의 어느 페이지 또는 어느 이미지 안에 포함되어 있는지 찾아준다.

중요한 점:
단순히 전체 이미지끼리만 비교하면 안 된다.
캡쳐 이미지는 PDF나 Word 문서 페이지의 일부를 잘라낸 이미지일 가능성이 크다.
따라서 원본 파일을 페이지 이미지로 렌더링한 뒤,
캡쳐 이미지가 그 페이지 안에 부분적으로 포함되어 있는지 찾아야 한다.

지원 파일 형식:
1. 기준 캡쳐 이미지

   - PDF

   - WEBP

- 페이지 번호 또는 이미지 번호
- 유사도 점수, 0~100점

  - 템플릿 매칭

- 원본 페이지 또는 이미지 미리보기
- 캡쳐 이미지와 매칭된 영역이 있다면 빨간 사각형으로 표시한 미리보기
- 페이지 번호는 PDF/DOC/DOCX/PPT/PPTX의 경우 1부터 시작

실패 파일 영역:
처리하지 못한 파일이 있으면 결과 아래에 “처리 실패 파일” 섹션을 만들고,
파일명과 실패 이유를 표시해줘.
단, 특정 파일 하나가 실패해도 전체 앱은 멈추면 안 된다.

전체 처리 흐름:
1. 사용자가 기준 캡쳐 이미지를 업로드한다.
2. 사용자가 원본 후보 파일 여러 개를 업로드한다.
3. 검색 시작 버튼을 누른다.
4. 기준 캡쳐 이미지를 OpenCV 이미지로 변환한다.
5. 원본 후보 파일을 하나씩 처리한다.
6. PDF는 각 페이지를 이미지로 렌더링한다.
7. DOC, DOCX, PPT, PPTX는 LibreOffice headless로 PDF로 변환한 뒤, 변환된 PDF의 각 페이지를 이미지로 렌더링한다.
8. 일반 이미지 파일은 그대로 비교 대상 이미지로 사용한다.
9. 각 비교 대상 이미지에서 기준 캡쳐 이미지와의 유사도를 계산한다.
10. 결과를 유사도 높은 순서로 정렬한다.
11. 상위 결과만 표시한다.

중요한 비교 알고리즘:
정확도를 높이기 위해 최소 3가지 방식을 함께 사용해줘.

A. ORB 특징점 매칭
- 캡쳐 이미지와 원본 페이지 이미지에서 ORB keypoint와 descriptor를 추출한다.
- BFMatcher 또는 FLANN 기반 매칭을 사용한다.
- 좋은 매칭점 개수를 계산한다.
- 충분한 매칭점이 있으면 homography를 계산해서 캡쳐 이미지가 원본 페이지의 어느 영역에 있는지 추정한다.
- homography가 성공하면 해당 영역의 bounding box를 구한다.
- ORB 점수는 좋은 매칭점 개수, inlier 비율, homography 성공 여부를 반영해서 0~100점으로 만든다.
- 캡쳐 이미지가 문서 페이지의 일부인 경우 이 방식이 가장 중요하다.

B. 템플릿 매칭
- 기준 캡쳐 이미지가 원본 페이지보다 작을 때 사용한다.
- cv2.matchTemplate을 사용한다.
- 단, 캡쳐 이미지와 원본 페이지의 크기 차이가 있을 수 있으므로 scale search를 해야 한다.
- 기준 이미지를 여러 스케일로 조정해서 비교한다.
- 권장 scale 범위:
  - 0.5
  - 0.75
  - 1.0
  - 1.25
  - 1.5
  - 2.0
- 각 scale에서 matchTemplate 결과의 최대값을 구한다.
- 가장 높은 점수와 위치를 저장한다.
- 템플릿 매칭 점수는 0~100점으로 변환한다.
- matching 위치가 있으면 bounding box를 저장한다.

C. 전체 이미지 pHash 비교
- 원본 이미지 파일이 캡쳐 이미지와 거의 같은 이미지일 때 사용한다.
- imagehash.phash를 사용한다.
- hash distance를 0~100점으로 변환한다.
- 이 방식은 보조 점수로 사용한다.

최종 점수 계산:
각 비교 대상 이미지마다 다음 점수를 구한다.

- orb_score
- template_score
- phash_score

final_score는 다음 규칙으로 계산한다.

final_score = max(
  orb_score,
  template_score,
  phash_score
)

단, ORB homography가 성공하고 inlier가 충분하면 ORB 점수에 약간의 보너스를 줘도 된다.
점수는 반드시 0~100 범위로 제한한다.

판정 기준:
- 85점 이상: 매우 유사
- 65점 이상 85점 미만: 유사
- 65점 미만: 낮은 유사도

결과 필터링:
- 기본적으로 40점 미만의 결과는 표시하지 않는다.
- 단, 결과가 하나도 없으면 “유사한 파일을 찾지 못했습니다”라고 표시하고,
  가장 높은 점수를 받은 후보 3개를 참고용으로 보여줘도 된다.

점수 계산 예시:
- template matching max_val은 일반적으로 0~1 사이이므로 score = max_val * 100
- phash는 hash distance가 낮을수록 유사하므로, 64bit hash 기준:
  score = max(0, 100 - distance * 100 / 32)
- ORB는 다음 요소를 조합:
  - good_matches 수
  - inlier 비율
  - homography 성공 여부
  예시:
  if good_matches < 8:
      orb_score = min(40, good_matches * 5)
  else:
      orb_score = min(100, 40 + good_matches * 2 + inlier_ratio * 40)
  homography 성공 시 score를 더 신뢰하되 100을 넘지 않게 한다.

테스트 요구사항:
앱을 완성한 후, 최소한 다음 상황을 고려해서 코드가 깨지지 않도록 해줘.

1. 캡쳐 이미지와 동일한 이미지 파일을 원본 후보에 넣은 경우 높은 점수로 찾아야 한다.
2. 캡쳐 이미지가 PDF 한 페이지의 일부인 경우 해당 PDF와 페이지 번호를 찾아야 한다.
3. DOCX 파일은 LibreOffice로 PDF 변환 후 페이지 단위로 검색해야 한다.
4. PPTX 파일도 LibreOffice로 PDF 변환 후 슬라이드 단위로 검색해야 한다.
5. 깨진 파일이나 지원하지 않는 파일이 섞여 있어도 앱이 멈추지 않아야 한다.
6. 업로드 파일이 없을 때 친절한 경고가 떠야 한다.
